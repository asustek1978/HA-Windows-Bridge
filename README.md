# HA Windows Bridge v1.2.0

Клиент для Windows 11 x64: передаёт показания компьютера в Home Assistant, показывает уведомления и по явному разрешению принимает команды управления Windows. Работает в трее через штатную интеграцию mobile_app. Отдельная интеграция для HA, MQTT и входящие порты на компьютере не требуются.

## Установка

1. Откройте [сборки для Windows](https://github.com/asustek1978/HA-Windows-Bridge/actions/workflows/windows-build.yml) и выберите последнюю успешную сборку ветки feature/windows-client-v1.
2. Скачайте артефакт HAWindowsBridge_v1.2.0_win-x64 и распакуйте архив полностью. Откройте PowerShell в распакованной папке и выполните `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Install-HAWindowsBridge_v1.2.0.ps1 -StartAfterInstall`. Установщик сверит SHA256, положит EXE в `%LOCALAPPDATA%\Programs\HAWindowsBridge` и создаст ярлык в меню «Пуск». Если клиент уже запущен, сначала выберите «Выход» в трее. При обновлении настройки и ключи сохраняются.
3. Откройте «Настройки...» через значок программы в трее. Он же используется для EXE и окна настроек.
4. Укажите хотя бы один адрес Home Assistant и долгосрочный токен доступа из профиля HA → «Безопасность».
5. Нажмите «Сохранить и подключить».

Пример локального адреса: http://192.168.1.100:8123. Пример внешнего: https://ha.polyarca.ru. Оба адреса должны вести к одному и тому же Home Assistant. Если локальный адрес недоступен, программа использует внешний. Для внешнего адреса обязателен HTTPS; сертификат проверяется обычными средствами Windows. При использовании локального HTTP токен передаётся внутри сети без шифрования: указывайте такой адрес только для доверенной домашней сети или пользуйтесь HTTPS/VPN.

Интервал передачи по умолчанию — 30 секунд, в настройках доступно 15–300 секунд. Поле «Проверять VPN-узел» можно оставить пустым или указать IPv4-адрес узла внутри VPN, например 10.77.78.1: клиент проверяет его по ICMP. Там же включается запуск программы при входе в Windows. Установщик переносит ранее включённый автозапуск на новый путь EXE.

EXE уже содержит среду .NET. Программа пока не подписана цифровой подписью, поэтому Windows может показать предупреждение о неизвестном издателе. Токен и идентификатор webhook хранятся в папке %LOCALAPPDATA%\HAWindowsBridge в зашифрованном виде через Windows DPAPI для текущей учётной записи.

## Датчики в Home Assistant

Устройство появится в «Настройки → Устройства и службы → Мобильное приложение». Точные entity_id зависят от имени компьютера и уже существующих сущностей — посмотрите их на странице устройства.

| Датчик | Значение |
| --- | --- |
| Загрузка процессора | Процент загрузки CPU |
| Загрузка памяти | Процент занятой оперативной памяти |
| Время бездействия | Минуты с последнего ввода |
| Время работы | Целые минуты после загрузки Windows |
| Всего памяти / Свободная память | ГиБ физической памяти |
| Свободно / Заполнен / Объём диска C: и других фиксированных томов | Свободное место, процент заполнения, объём |
| Wi-Fi подключён / Сеть Wi-Fi / Сигнал Wi-Fi | Состояние подключения, SSID и качество сигнала в процентах |
| VPN-интерфейс активен / VPN-интерфейс | Состояние и имя WireGuard, OpenVPN и других VPN-интерфейсов |
| VPN-узел отвечает | Проверка ICMP, если в настройках указан его IPv4-адрес |
| VPN-узел — задержка | Время ответа ICMP, если VPN-узел доступен |
| Шлюз сети / роутер отвечает / задержка | IPv4-шлюз Windows и его ответ по ICMP |
| Последний handshake WireGuard / время после него | Отчёт `wg.exe` для активного VPN-интерфейса, если WireGuard установлен и разрешает чтение; на простаивающем канале время может расти |
| Подключение к Home Assistant / задержка | Используемый локальный либо внешний адрес и время ответа API |
| Температура процессора / Мощность процессора | Если оборудование предоставляет данные |
| GPU — загрузка / температура / горячая точка / вентилятор / мощность / видеопамять | Отдельно для доступных видеокарт и показателей |
| Температура диска | Отдельно для дисков с аппаратным датчиком |
| Ресурс SSD / наработка / ошибки SMART / проблемы диска | При наличии соответствующих аппаратных показателей LibreHardwareMonitor; ошибки секторов и ресурс ниже 15% отмечаются как проблемы. Общий датчик объединяет известные накопители |
| Управление Windows из HA / Последняя команда Windows | Разрешение команд и результат последнего выполнения |
| IP-адрес | Адрес выбранного сетевого адаптера |
| Скорость загрузки / Скорость отдачи | Трафик адаптера в Мбит/с |
| Последний отчёт | Время последней передачи данных |
| Интервал отчётов / версия моста | Диагностика клиента и его настроек |
| Питание от сети / Заряд аккумулятора | Состояние внешнего питания и заряд при наличии аккумулятора |
| Сеанс заблокирован | После первого события блокировки/разблокировки во время работы клиента |
| Экран включён | После первого события питания дисплея во время работы клиента |

При выключенном компьютере HA хранит последнее состояние аппаратных датчиков. Пакет v1.2.0 ниже вычисляет «Компьютер Windows ASUSTEK78 в сети» по времени последнего отчёта: после трёх пропущенных интервалов плюс 30 секунд он переключается в «выключен». Обычные сохранённые показатели температуры и нагрузки при этом остаются последними полученными значениями.

Если вы уже запускали английскую сборку, при первом подключении программа обновит исходные названия устройства и датчиков через mobile_app. Датчик «Время работы» сохраняет минуты и прежние unique_id и entity_id. Имена, которые вы меняли вручную в HA, сохраняют пользовательские настройки.

Аппаратные показания считываются через [LibreHardwareMonitorLib](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor) (MPL 2.0, включена в EXE). Доступность температуры, оборотов, мощности, SMART и GPU зависит от оборудования, драйверов и прав Windows. Если датчик недоступен, новая сущность для него не создаётся; ранее доступная сущность при потере показаний переходит в «Неизвестно». Порог ресурса SSD — 15%, ошибки секторов показаны отдельно; счётчик ошибок сам по себе не является окончательным диагнозом. Для SSID и сигнала Wi-Fi Windows может потребовать доступ к местоположению. Активный VPN-интерфейс сам по себе не подтверждает WireGuard handshake: для проверки узла укажите его IPv4. Если ICMP заблокирован, доступность узла и роутера будет показываться как «выключен». Для handshake нужен `wg.exe` в стандартной папке WireGuard и права на чтение его данных.

## Управление Windows из Home Assistant

Команды по умолчанию **выключены**. Для включения откройте настройки значка в трее, отметьте «Разрешить команды из Home Assistant», скопируйте «Ключ команд HA» и нажмите «Сохранить и подключить». Ключ хранится на Windows в зашифрованном виде через DPAPI. Пять команд: блокировка сеанса, сон, перезагрузка, выключение, отмена запланированного выключения. Перезагрузка и выключение назначаются с задержкой 60 секунд; отменить их можно командой отмены или локально командой `shutdown /a`.

1. Найдите в «Инструменты разработчика → Действия» старое адресное действие `notify.mobile_app_...` именно этого компьютера. Действие `notify.send_message` для обычных уведомлений не передаёт дополнительное поле `data` и для команд не подходит.
2. Добавьте в `/config/secrets.yaml` строку `ha_windows_bridge_control_key: "СКОПИРОВАННЫЙ_КЛЮЧ"`.
3. Скопируйте полный [пакет v1.2.0](examples/ha_windows_bridge_package_v1.2.0.yaml) в `/config/includes/packages/` (для `packages: !include_dir_merge_named includes/packages`). **Удалите старый файл `ha_windows_bridge_commands_v1.1.0.yaml` из этой папки**: иначе пять скриптов определятся дважды. В этом режиме файл начинается с имени пакета `ha_windows_bridge:`, а `script:`, `template:` и остальные разделы идут уровнем ниже. Для ASUSTEK78 действие `notify.mobile_app_kompiuter_windows_asustek78` уже подставлено.
4. Проверьте конфигурацию HA и перезапустите HA. В HA появятся пять скриптов и двоичный датчик доступности. Найдите на странице устройства фактический entity_id датчика «Последний отчёт». Если он отличается от `sensor.kompiuter_windows_asustek78_poslednii_otchet`, впишите его один раз в помощник «Windows — entity_id последнего отчёта». В помощнике «Windows — интервал отчётов» установите то же число секунд, что в настройках клиента (по умолчанию 30). Проверьте сначала блокировку Windows, затем добавьте [готовую карточку v1.2.0](examples/ha_windows_bridge_dashboard_v1.2.0.yaml) через редактор кода панели. Проверьте entity_id строк карточки на странице устройства: HA может иначе транслитерировать русские названия, а SMART датчики получают индивидуальные суффиксы дисков.

При неожиданной потере связи пакет создаёт постоянное уведомление HA и отправляет сообщение через `slava_max.send_message` в стандартного получателя, заданного в вашей интеграции MAX Messenger Notifications. При восстановлении уведомление HA убирается. После команд сна, выключения и перезагрузки из HA тревога подавляется до следующего подключения; если команда не выключила ПК, ожидание сбрасывается через три минуты. Если питание отключили вручную, сообщение придёт. При появлении общего признака SMART-проблем пакет вызывает `slava_max.send_emergency` в настроенный аварийный канал MAX. Для обоих действий требуется установленная и настроенная интеграция MAX; если её нет, удалите два действия `slava_max.*` из файла пакета до установки.

## Установка, обновления и журнал

В трее есть «Проверить обновления...»: клиент проверяет опубликованный релиз GitHub, сравнивает версии и открывает страницу загрузки по запросу. Пока релиза нет, скачайте последнюю успешную сборку GitHub Actions. Загрузка и установка выполняются вручную; клиент сам не запускает скачанный EXE. Для установки новой версии закройте старую программу в трее, распакуйте новый архив и запустите приложенный установочный скрипт. Не удаляйте `%LOCALAPPDATA%\HAWindowsBridge`: там сохранены настройки, токен и ключ команд.

«Открыть журнал» в меню трея показывает ошибки связи и проверки обновлений. Журнал находится в `%LOCALAPPDATA%\HAWindowsBridge\bridge.log`, размер ограничен ротацией при 1 МиБ. В разделе «Диагностика» HA появятся версия и интервал отчётов. EXE пока не подписан цифровым сертификатом: установочный скрипт и SHA256 проверяют целостность архива, но не убирают предупреждение SmartScreen о неизвестном издателе.

Команда принимается только при включённом управлении, совпадении ключа и времени создания сообщения в пределах двух минут. Текст произвольной команды или команда оболочки не выполняется. Не показывайте ключ в карточках панели: пользователь с доступом к этим скриптам сможет выключить компьютер. При выключении ПК уведомительный канал отключится, и отмена из HA уже может не дойти.

## Строки «Неизвестно» и проверка уведомлений

Строка в разделе «Уведомители» — сущность для отправки уведомлений. До первой успешной отправки её состояние «Неизвестно»; затем Home Assistant показывает время последнего сообщения. На странице устройства откройте эту сущность и скопируйте её entity_id. Для проверки в «Инструменты разработчика → Действия» вызовите действие `notify.send_message`, подставив свой entity_id:

    action: notify.send_message
    target:
      entity_id: notify.vasha_sushchnost
    data:
      title: Home Assistant
      message: Проверка уведомления на компьютере

Программа должна работать и показывать в трее состояние «Локальный адрес — подключено» или «Внешний адрес — подключено». Если сущность уведомлений появилась недавно, может понадобиться один раз перезапустить Home Assistant. Режим «Не беспокоить» в Windows может скрывать баннеры.

Строка «Неизвестно» в разделе «Диагностика» — трекер местоположения, который Home Assistant автоматически создаёт для интеграции mobile_app. Клиент не определяет местоположение компьютера, поэтому у трекера нет состояния. Если он не нужен, отключите только эту сущность на странице устройства в Home Assistant; уведомления и датчики продолжат работать.

Сейчас уведомление поддерживает заголовок и текст. Изображения, кнопки действий и замена сообщения по тегу пока не реализованы. Управление компьютером из HA доступно через защищённые команды.

## Сборка из исходников

Установите .NET 10 SDK на Windows 11 x64. В корне репозитория выполните:

    dotnet publish src/HaWindowsBridge/HaWindowsBridge.csproj -c Release -r win-x64 --self-contained true -o dist

Результат: dist/HAWindowsBridge.exe. GitHub Actions перед сборкой проверяет разрешение команд и отказ при неверном ключе, истёкшем времени или запрещённом действии, затем прикладывает EXE, установочный скрипт и SHA256 как артефакт. Опубликованного релиза может пока не быть; проверка обновлений сообщит об этом.

## Как устроено подключение

Клиент регистрирует устройство через POST /api/mobile_app/registrations, создаёт датчики вызовами register_sensor и обновляет их пакетами update_sensor_states через webhook. Уведомления получает через /api/websocket и mobile_app/push_notification_channel. Обычные уведомления отображаются как текст; команды выполняются только при включённом управлении и с верным ключом. Для внешнего адреса используется HTTPS/WSS.

Код проекта написан отдельно и не копирует исходники HASSConnect. Служебные имена методов, JSON-ключи, unique_id и название исполняемого файла оставлены латиницей для совместимости с Home Assistant и сохранения уже созданных сущностей.
